## 规则

1. 一律**中文叙述 + 英文代码**；类名/方法名保留英文原样并加反引号。
2. 每条 finding 必须**逐行核对过源码**；不确定的行号/行为标注「需实测」或「高概率」，**禁止编造**。
3. 不确定收益不要写具体百分比；写「量级：每 tick 数十到数百次分配」这类可验证表述。
4. 修复方案**优先纯 Java**（零依赖），其次使用已在 classpath 的 fastutil / JOML；再其次才提新增库。
5. **禁止修改 `src/` 下的任何文件** —— 你的产出只有 `docs/` 下的 markdown。
6. 每条 finding 若「无法用 Mixin 实现」，仍然要收录，并在「注入方式」写 `不可 Mixin` + 理由，同时收进 `docs/perf/11-upstream-issues.md`（由 Lead 汇总，你只需在文末列出候选）。
