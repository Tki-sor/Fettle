# 09 · 🅔 第三方 mod BE 沉睡：授权边界与实施约束

Lithium 的 BE sleeping **只覆盖原版方块实体**，第三方 mod 的 BE 是空白——这是本条路线唯一的高收益区，也是最容易把整合包搞坏的地方。
你已授权开展，下面是我据此定义的**可执行边界**（写进代码即视为契约）。

## 9.1 硬约束（缺一不可）

| # | 约束 | 实现方式 |
| --- | --- | --- |
| 1 | **默认关闭** | `beSleeping.enabled = false`；未开启时相关 mixin 由 `FettleMixinPlugin` 直接拒绝应用 |
| 2 | **逐类白名单** | `beSleeping.classes = []`，元素为**全限定类名**；空列表 = 功能完全不生效。默认值是空 |
| 3 | **先观察后沉睡** | 每个类必须先在**观察模式**下采集 ≥ `observeTicks`（默认 1200 tick = 1 分钟）行为画像，期间**零行为变更** |
| 4 | **跳过上限（心跳）** | 连续跳过最多 `maxSkipTicks`（默认 20 = 1 秒）后强制 tick 一次，保证"长期不变"的 BE 不会永久失联 |
| 5 | **一键回退** | `/fettle besleeping off` 立即停用并唤醒全部；配置文件关闭同效；**重启后一律回到观察态** |
| 6 | **失败自动拉黑** | 任何异常、或"唤醒后首个 tick 的产出与观测基线不符" → 该类立即移除白名单并**本次运行内永久禁用**，只记日志，不弹窗、不崩游戏 |

## 9.2 只有"可证明无副作用"的类才允许进入白名单

观察期对每个类统计，**四项全为零**才成为候选：

1. tick 内是否修改自身持久化状态（NBT 前后快照对比）；
2. 是否调用 `setChanged()` / `sendData()` / `notifyUpdate()`；
3. 是否写 level（方块更新、方块实体创建/删除、发包）；
4. 是否读取外部可变状态并据此分支（红石、邻居库存、玩家位置、`level.getGameTime()` 绝对时间——**这条会直接否决**）。

## 9.3 沉睡期间的语义

- **只跳过 `tick()`**；`saveAdditional`、`getUpdatePacket/getUpdateTag`、`onDataPacket`、`getCapability`、`setRemoved` 等**一律照常**；
- 必须实现的**唤醒条件**（任一满足即唤醒 + 复位心跳计数）：方块更新/邻居变化、红石信号变化、比较器输入变化、区块重新加载、玩家进入渲染距离、收到交互/网络包、被 capability 查询、被其它 BE 显式引用。

## 9.4 明确不做

- 红石元件、动能/流体网络成员、依赖随机刻的 BE；
- 用 `getGameTime()` 做绝对时间判断的 BE（沉睡会改变其时间基准）；
- 任何**第三方 mod 有自研 tick 循环**的 BE（AE2 走 `ServerTickEvent`、Mekanism 走 `CommonWorldTickHandler`）——那些根本不经过原版 tick 分派，我们管不着；
- 任何未经观察期数据的类。

## 9.5 上线一个类之前必须有的三份证据

1. **观察期数据**：该类在目标场景下的 tick 次数、是否全零（我们已有记录器 + `/fettle micro` 工具链）；
2. **A/B 实测**：`/fettle feature` 开关两组，用现有逐 tick 记录器对比（总 tick + 该类段）；
3. **行为门禁**：`./gradlew runGameTestServer`（现有 CI 已跑，退出码 = 失败测试数）在启用前后都通过。

## 9.6 试点建议

**不要一上来挑 AE2/Mekanism**（它们不吃原版 tick 分派）。第一步应该先用一个**可控、无副作用**的类把整条机制跑通（例如 Create 里纯展示型/无逻辑的 BE），把"观察 → 沉睡 → 唤醒 → 回退 → 自动拉黑"全链路验证一遍，再考虑扩大到真实的第三方 mod。
